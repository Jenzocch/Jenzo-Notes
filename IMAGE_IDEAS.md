## Implemented

- Shared creation dialog → Image + idea. Desktop uses Chromium's file input; Android reuses existing native `files.open` because its WebView has no HTML chooser. No new Android permission or native service is introduced. An Android picker creates a temporary UUID copy; only that unreferenced copy is queued for existing deferred attachment cleanup, never the original document path.
- Explicit non-private/ordinary-note acknowledgment precedes recognition and collection. Original PNG/JPEG/WebP bytes (10 MB maximum), SHA256, filename, capture time, optional source URL and user-supplied source date are preserved through existing attachment and card storage. URLs are not fetched. Existing sync/backup behavior is retained; no new destination/account is configured.
- Windows uses installed `Windows.Media.Ocr` through bundled PowerShell, with fixed code, encoded JSON arguments, bounded input/output, a 30-second timeout, hidden process and normal success/error/timeout temporary-file cleanup. No dependency, language-pack install, cloud fallback or execution-policy modification. This environment has `zh-Hant-TW`, `zh-Hans-CN`, `en-US`; Indonesian fixture uses English recognition and manual correction, without claiming dedicated Indonesian support.
- Original OCR, corrected transcription, explicit transcription-check state and collection reason are separate. An image-only idea can be saved without text. No image meaning/visual inference or confidence probability is invented. Transcription checking does not certify the original claim.
- Unreviewed OCR is searchable, but excluded from source excerpts supplied to cited document/investigation workflows. Checked transcription and user annotations retain explicit labels. Retained image metadata is transported through the existing card properties bag (R9 preserves ordinary user properties); no destructive schema change.
- Repeated image bytes open the existing record without overwriting reasons/text. Corrections retain raw OCR and up to 100 prior metadata revisions, visible in the Info panel. At the bound, further revision stops rather than dropping history. Existing card editor, versions, sync and backups remain available. Generic rich-editor body edits invalidate image citation authority; restore the earlier image-collection version before revising it through the dedicated correction panel. Those edits are never silently replaced.
- Cited evidence checks current original bytes, attachment existence/attachment membership, exact canonical body and version. Changed/removed original or text invalidates citations, exports, task proposals and accepted graph writes. Local in-flight persistence is revoked on attachment mutation, even delete/restore during a pending vault read. Source status refresh also observes the selected originals. Guards stop before dispatch/commit; this is not a distributed rollback after native IO begins, and external filesystem changes are checked when the original is read rather than watched by a new daemon.
- Existing evidence → manual interpretation → accepted graph relationship → confirmed export/task workflows are reused. Private retained provenance fails closed; the source/evidence viewer does not expose private records through the new ordinary-image revision UI.

## Reading language and R11 follow-up

New Jenzo profiles default to `zh-TW`; explicitly persisted app-language choices remain available. Operating-system/source languages do not replace this reading default. Locally generated investigation explanations, task proposals and exported document headings support Traditional Chinese while quoted Indonesian originals, names, product identifiers, numbers and units remain verbatim. Recognition-language choices are labelled in Chinese. OCR is transcription, not translation or Indonesian semantic understanding.

Search remains literal keyword retrieval. A Chinese phrase does not semantically retrieve an Indonesian-only passage; user-added Traditional Chinese collection notes can make that record discoverable by those exact Chinese terms. This is manually annotated retrieval, not automatic translation or multilingual embedding search. The original/corrected Indonesian text and original image stay available for comparison. Unreviewed OCR remains excluded from evidence.

No installed local Indonesian-to-Traditional-Chinese translator or multilingual embedding model was established in this task. Options for a later approved slice are: manual reading notes/glossary with original parallel text; an explicitly selected, locally installed translation model with protected named/numeric spans and human review; or a local multilingual embedding index with reindexing/version/privacy boundaries. Model/language-package downloads and cloud disclosure require separate authorization; no new package, account or upload is added here.

R11 closes the original SourceWorkbench snapshot-export gap: source-derived encrypted drafts, saved notes and plaintext exports use retained-source guards, with rechecks after consent and every vault read/CAS retry, plus synchronous dispatch checks. Selected card/fragment/attachment writes revoke pending operations, including delete-and-restore. Source changes/removed images trigger a visible stale-source alert and disable persistence, preserving the manual draft. Re-search/recompose is required. The guard boundary is before dispatch, not rollback after native IO has begun.

## Meeting records and growth: next bounded slice

Existing TXT/Markdown/DOCX/PDF-text import already retains original attachments and produces searchable/citable text. This slice does not claim a new meeting-classification UI. Use the current imported note and source investigation to review exact passages and manually accept derived tasks/associations. A PDF text layer is not OCR; a video link is not complete video understanding.

The next small meeting-text enhancement will classify explicitly stated discussion, decisions, action proposals and unresolved questions, preserving original text/version and checking every quoted span. Unstated owner/deadline remain unknown. Confirm extracted results before writing tasks/project links, and distinguish proposed from approved decisions. Private meeting content stays within the existing vault/privacy rules, with no new cloud upload. Use synthetic meeting examples until the user supplies a file.

“Grow with me” means retaining user corrections, decision reasons and later outcomes as revisions, with old interpretations invalidated/reviewed when sources change. It does not mean automatic model training or inferring the user's beliefs. Historical contradictions, knowledge revision across all notes, audio transcription, large-document parsing and external services remain subsequent work; no automatic full-library OCR/AI scan is added.
