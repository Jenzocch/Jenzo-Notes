# Private secretary v2: current slice and evidence

This report supersedes the earlier `LOCAL_SECRETARY_QA.md`. It covers the new Windows private vault and independent-review fixes, not a completed private/offline release of the whole app. The base remains PR #1's merge `b1c9e88`; PR #2 remains draft. No merge, deployment, new account/credential, OS ACL change, real microphone permission, paid AI or private-data migration was performed.

## Current persistence boundary

New secretary notes, tasks, reminder operations, mock budget and source-workbench drafts/snapshots live in one v2 encrypted vault. The renderer never puts their bodies, source snapshots, task titles, index terms or key material into IndexedDB/localStorage. Search scans decrypted private records only in memory while unlocked, alongside read-only legacy note/fragment retrieval. New private capture and document save go to the vault. They deliberately do not enter legacy plaintext note sync/backups; existing legacy functionality and original data remain unchanged.

Windows main-process `safeStorage` wraps a random AES-256 data key. Only the OS-protected wrapped key, authenticated metadata, random IV, GCM tag and ciphertext are stored in `private-secretary-v2/secretary-v2.vault.json`; there is no adjacent raw key file. Metadata/key wrapping/revision are included in AES-GCM AAD. Atomic writes use encrypted temporary files, sync and rename. No chmod/ACL mutation is used. Invalid records, unsupported formats, failed authentication/key protection and unavailable runtime fail closed. Capability loss drops the session. Concurrent writes use serialized main-process operations and revision CAS; the client retries conflicts with fresh data and never loses unrelated committed records.

The app starts locked. Explicit unlock is needed after renderer reload/process restart. Lock clears private UI state and closes any pending voice request; read/write require an unlocked native session. OS lock-screen and main-frame reload trigger lock. This is an application session lock, not biometric authentication or a separate Windows-user boundary. JS memory erasure is not guaranteed; native key buffers are cleared on lock.

All new vault IPC verifies the actual main window, main frame and exact app URL; no arbitrary file-path or migration IPC is exposed. Main navigation now uses exact dev origin/path or the packaged index file rather than a prefix/all-file allowlist. Other legacy IPC endpoints have not all been independently hardened. Existing sandbox/context isolation/no-node-integration are retained.

Browser, Android and other platforms without this new verified native adapter show unsupported and disable sensitive persistence. They never fall back to plaintext, WebCrypto keys in IndexedDB, installed language packs or a cloud service. Android already has a credential Keystore, but its secretary-vault bridge is not implemented or device-verified; unsupported does not mean Android has no OS key facilities. macOS/Linux adapters are intentionally outside this Windows slice.

## Independent review fixes

- R1: new private task and operation changes share one encrypted commit. Completing/deleting the linked task cancels its reminder; reopening alone does not rearm it. Title/date edits update the operation. Recurrence updates both private task due time and displayed wall time derived from `nextDueAt` + zone. Cancel-only still retains the task. Old plaintext operation preferences are not auto-executed or auto-migrated.
- R2: proposals carry issuance, five-minute expiry and whether they were already overdue when issued. Final confirmation checks current time. A previously future target that has passed requires a fresh preview; a fresh overdue proposal requires explicit acknowledgement of immediate catch-up. Expired consent cannot write. Retry of an already committed identical operation remains idempotent, even after task edits, via immutable proposal binding.
- R3: generated headings/body are literal text, source URLs are parsed/normalized and credentials/control characters/markup are rejected as active URLs. Originals stay unchanged; unsafe supplied URLs remain labelled literal evidence. Edited export is enclosed in a dynamically sized text fence, retaining content and source IDs while preventing raw HTML, scripts, Markdown/reference images, autolinks and fence escapes from becoming active in standard Markdown renderers. This exports inert text rather than richly rendered Markdown. App sanitization alone is not the export policy.

## Versioned backup and migration

The UI exports encrypted v2 backups on explicit selection. Restore decrypts/authenticates and previews format/counts first; cancellation changes nothing. Confirmation requires unchanged revision and saves an encrypted rollback checkpoint before replacement. Subsequent mutations/locking invalidate pending previews. Checkpoints can be previewed and restored with the same confirmation path. Backups are OS-user/context bound; they are not portable recovery and cannot promise recovery after DPAPI/OS keys are lost. Separate portable recovery/key escrow needs a reviewed design before real use.

`electron/secretary-migration.cjs` is a **synthetic-only harness**, not an IPC route or startup migration. It accepts explicitly marked v1 synthetic snapshots, previews counts/version/digest, binds confirmation to source digest and target revision, requires an encrypted checkpoint before writing, preserves the original snapshot encrypted and normalizes drafts to v2. Old reminder records are retained as inactive evidence requiring new consent, never reactivated. Cancel, failed backup, changed source/target, collisions and unknown versions fail without changing the source. Tests restore the previous target through the encrypted checkpoint. No real IndexedDB, localStorage, legacy credentials, user-selected notebook or reviewer workspace is read/migrated by this harness.

Real migration remains disabled. A later approved flow must select the exact source, show counts/conflicts/bytes without silently reading unrelated data, verify the encrypted backup and restore before commit, preserve source data until separate deletion approval, and handle OS-key lifecycle/account transfer. Converting old credential vaults or the entire note database is not included here.

## Remaining release gates

This new slice removes plaintext/adjacent-key persistence for **new secretary data and drafts**. Existing notes/indices, Android legacy task drafts and existing provider/MCP/Google credential vaults have not been migrated or certified; their previously documented storage risks remain. Therefore the whole-app private-secretary release gate is still open. DPAPI protects against a copied wrapped key without OS access/other Windows users; it does not stop same-user malware, an unlocked compromised renderer or OS compromise. The official [Electron 44 safeStorage documentation](https://github.com/electron/electron/blob/v44.0.0/docs/api/safe-storage.md) defines that boundary.

Cloud paid generation remains gated, but provider discovery/key validation, legacy sync/backups, web imports, updates and explicit model downloads have not been globally disconnected. There is no claim that the entire app is offline. Real connectors/scopes/OAuth, Android/macOS native vaults, portable recovery, real voice permission/device testing, background/lock-screen alarm delivery and a trusted cross-device budget coordinator remain unimplemented/unapproved. No authentic Claude review has been received. Independent Codex audit supplied R1–R3; the new exact head must be independently re-reviewed.
